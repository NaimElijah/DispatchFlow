DispatchFlow core, layer by layer

Every top-level Java type in the core service, src/backend/core/src/main/java, except its entry point DispatchFlowApplication, placed in its hexagonal layer and its bounded context. Nested types, such as an error's variants, sit inside their file's type. Read it top to bottom: a request enters at a web adapter, runs a use case in the application layer, changes aggregates in the domain, and is stored by a persistence adapter.

The database sits at the bottom of the picture, but it does not sit under the domain. Every dependency points toward the domain. The persistence adapters depend upward: they implement the application layer's port/out interfaces and rebuild aggregates from rows. The domain never imports Spring, jOOQ or SQL (ADR-001).

The ArchUnit tests in src/backend/core/src/test/java/com/dispatchflow/architecture/ enforce the domain's purity and the application layer's imports.
